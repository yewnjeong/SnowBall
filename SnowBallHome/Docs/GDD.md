# SnowBall — 게임 기획서 (GDD v0.1)

> Unity 6000.6.0f1 / URP / 3D 3인칭 / 물리 기반 운반 게임
> 프로젝트: `SnowBallHome/`

---

## 0. 한 줄 요약

> **굴러 내려간 눈사람 머리를, 산 위 우리 집까지 도로 밀어 올린다.**

아이는 관성이 없어 칼같이 멈추지만, 눈덩이는 관성 덩어리다.
이 **두 물체의 물성 대비**가 게임 전체의 재미를 만든다.

---

## 1. 장르와 톤

| 항목 | 내용 |
|---|---|
| 장르 | 3인칭 물리 운반 / 조작 극복 (physics-based traversal) |
| 시점 | 3D 3인칭, 어깨 뒤 추적 카메라 |
| 플레이 시간 | 1회차 25~40분 (숙련 시 8~12분) |
| 톤 | 겉은 따뜻한 동화, 속은 집요한 물리 도전 |
| 모티브 | `Get To Work` 계열 — 조작이 의도적으로 불편하고, 그 불편함을 몸으로 익히는 것이 성장 |

### 1.1 "의도적 불편함"의 정의 (설계 원칙)

이 게임에서 불편함은 **버그가 아니라 규칙**이다. 단, 세 가지를 지킨다.

1. **불편함은 항상 일관적이다.** 같은 입력은 항상 같은 결과를 낳는다. 랜덤으로 실패하게 만들지 않는다.
2. **실패의 원인은 항상 보였어야 한다.** 화면 밖에서 날아온 것에 당하지 않는다. (마을 아이의 눈덩이도 반드시 예비 동작 + 궤적 예고)
3. **되감기는 벌이지, 벽이 아니다.** 죽음/게임오버 화면 없음. 굴러 떨어지면 그냥 다시 밀면 된다. 손실은 오직 **시간과 눈덩이 크기**.

## 2. 핵심 루프

```
     눈덩이를 민다  ──▶  경사를 오른다  ──▶  장애물/이벤트 발생
          ▲                                        │
          │                                        ▼
     다시 붙잡고 자세를 잡는다  ◀──  눈덩이가 뒤로 굴러간다
```

한 사이클은 보통 **5~15초**. 이 짧은 리듬이 계속 반복되며,
플레이어는 "언제 밀고 / 언제 잡을지"의 판단을 점점 빠르게 하게 된다.

## 3. 조작 (확정)

| 입력 | 동작 | 세부 규칙 |
|---|---|---|
| `W A S D` | 아이 이동 | **입력이 없으면 즉시 정지.** 가속/감속 관성 없음 |
| `Shift` (홀드) | 눈덩이 붙잡기 | 근처 + 바라보는 방향일 때만 성립. **잡는 동안 이동 불가** |
| `Shift` 뗌 | 놓기 | 즉시 해제 |
| 잡은 중 `WASD` 입력 | **자동으로 손을 뗌** | 기획 요구사항 |
| 마우스 | 카메라 회전 | |
| `R` (홀드 1.5초) | 체크포인트 되감기 | 스스로 꼬였을 때 탈출용 |

### 3.1 Shift 잡기가 왜 재미있는가 (핵심 기믹)

Shift는 "줍기" 버튼이 아니라 **브레이크**다.

- 경사에서 아이가 손을 떼면 → 눈덩이는 중력으로 **뒤로 굴러 내려간다**
- Shift를 잡으면 → 눈덩이는 그 자리에 **고정된다**
- 그런데 잡는 동안엔 **한 발짝도 못 움직인다** → 전진이 0

즉 플레이어는 매 순간 이 선택에 묶인다:

> **안전하지만 아무 진전이 없다 (잡기)** ↔ **전진하지만 굴러 떨어질 위험 (밀기)**

이 딜레마가 게임 전체를 지탱하는 유일한 축이다. 다른 모든 요소는 이 축을 흔드는 변주다.

### 3.2 잡기에 제한을 둘 것인가 — **결정 필요 ⚠️**

Shift 잡기가 무제한이면 "위험할 땐 그냥 계속 잡고 있으면 된다"가 되어
딜레마의 한쪽이 무료가 된다. 세 가지 안:

| 안 | 내용 | 평가 |
|---|---|---|
| **A. 악력 게이지 (구현됨)** | 잡고 있으면 게이지 감소, 0이 되면 강제로 놓침. 경사가 급할수록 빨리 닳음. 놓고 있으면 회복 | 딜레마가 시간축으로 살아남. **현재 기본값** |
| B. 무제한 + 전체 타이머 | 해질녘까지 도착해야 함 | 동화 톤과 맞지만 압박이 추상적 |
| C. 완전 무제한 | 순수 조작 도전 | 가장 관대하나 긴장이 약함 |

**→ A안으로 구현했으나, `gripDrainFlat` / `gripDrainOnSlope` 를 0으로 두면
그 자리에서 C안이 되도록 설계했다.** 플레이해보고 직접 비교할 수 있다.

현재 값: 최대 100, 평지 소모 8/s, 경사 20°에서 30/s, 회복 25/s.

## 4. 두 물체의 물성 (가장 중요한 수치)

### 4.1 아이 (Player)

| 속성 | 값 | 의도 |
|---|---|---|
| 이동 속도 | 3.2 m/s | 눈덩이보다 약간 빠름 |
| 가속 | **즉시** (관성 0) | 기획 확정 사항 |
| 회전 속도 | 720 °/s | 방향 전환은 시원하게 |
| 질량 | 35 kg | 눈덩이보다 가벼워야 "밀리는" 느낌 |
| 밀기 힘 | 220 N | 접촉 시 눈덩이에 가해짐 |

### 4.2 눈덩이 (Snowball)

| 속성 | 값 | 의도 |
|---|---|---|
| 시작 지름 | 0.8 m | 아이 허리 높이 |
| 목표 지름 | 1.6 m | 엔딩 A 조건 |
| 최대 지름 | 2.2 m | 이보다 커지면 못 민다 |
| 질량 | `지름³ × 45` kg | 0.8m → 23kg, 1.6m → 184kg |
| 최대 구르기 속도 | 9 m/s | 통제 불능 방지 |
| 선형 저항 | 눈 0.20 / 빙판 0.01 | |
| 각 저항 | 눈 0.35 / 빙판 0.05 | |

**질량이 지름의 세제곱이라는 점이 결정적이다.**
지름이 2배가 되면 질량은 8배가 된다 → 커질수록 급격히 무거워진다.

### 4.3 눈덩이 성장 = 양날의 검

```
눈밭을 구른 거리 ──▶ 지름 증가 ──┬──▶ (+) 작은 장애물을 뭉개고 통과
                                 ├──▶ (−) 질량 폭증, 밀기 급격히 힘듦
                                 └──▶ (−) 관성 증가, 멈추기 어려움
나무/바위 충돌 ─────▶ 지름 감소 (깎임)
```

| 이벤트 | 지름 변화 |
|---|---|
| 눈밭 1m 구름 | +0.004 m |
| 빙판 1m 구름 | 0 (안 커짐) |
| 나무 충돌 | −0.06 m |
| 바위 충돌 | −0.10 m |
| 연못 빠짐 | −0.25 m + 체크포인트 되감기 |
| 마을 아이 눈덩이 피격 | −0.02 m + 충격 |

플레이어는 **"얼마나 크게 키워서 갈 것인가"**를 스스로 조절한다.
크게 키우면 엔딩 A에 가깝지만 후반 산길이 지옥이 된다.

## 5. 스테이지 구성

### 프롤로그 — 눈사람 만들기 (미구현)

아이가 눈사람 몸통 위에 머리를 올린다 → 머리가 굴러 떨어진다 → 산 아래로 사라진다
→ 아이가 산을 내려간다 → 눈덩이 발견 → **여기서 조작 권한이 넘어온다.**

> 연출 노트: 이 40초 동안 "위로 올라가야 한다"는 방향감각을 반드시 심어야 한다.
> 카메라가 마지막에 산 정상의 집을 한 번 비춰준다. 그게 목표다.

---

### 스테이지별 수치표

이 표가 그대로 `CourseDefinition.asset` 의 값이다. 밸런싱은 여기만 고치면 된다.

| # | 이름 | 길이 | 경사 | 폭 | 굽이 | 체크포인트 | 장애물 |
|---|---|---|---|---|---|---|---|
| ① | 눈밭 | 60 m | 6° | 7.0 m | 0° | 1 | 없음 — 조작 학습 |
| ② | 숲 | 90 m | 14° | 4.5 m | 70° | 2 | 나무 14, 바위 2 |
| ③ | 얼어붙은 계곡 | 80 m | 11° | 6.0 m | 35° | 3 | 빙판 7, 연못 2, 바위 3 |
| ④ | 강아지 구간 | 50 m | 9° | 7.0 m | 20° | 1 | 강아지 1, 나무 3 |
| ⑤ | 마을 | 70 m | 12° | 6.5 m | 40° | 2 | 마을아이 4, 엄폐물 4 |
| ⑥ | 마지막 산길 | 120 m | 20° | 4.5 m | 90° | 1 | 나무 8, 바위 3, 빙판 5, 연못 1, 강풍 |

**생성 결과: 구간 78개, 총 고도 106.4 m**

### 스테이지별 설계 의도

- **① 눈밭** — 밀어본다 → 경사에서 손 떼면 굴러간다(체감) → Shift로 잡아본다. 장애물 없음.
- **② 숲** — 나무가 **깎이는 벌**을 준다. 처음으로 "빨리 가려다 손해 본다"를 배운다.
- **③ 계곡** — 빙판 위에선 **아이도 미끄러진다**(즉시 정지 규칙의 유일한 예외). 이탈률 1위 예상 구간이라 체크포인트를 3개로 촘촘히.
- **④ 강아지** — 적이 아니라 **신난 것**. 1.2초 예비 동작 후 들이받는다. 아이가 다가가면 도망. 쫓아 보내려면 눈덩이에서 손을 떼야 한다 → 딜레마의 변주.
- **⑤ 마을** — 1.5초 조준선 예고 후 투척. 엄폐물 뒤는 안전하지만 길이 멀다 → **빠른 길 vs 안전한 길**.
- **⑥ 산길** — 신규 요소 없음. 전부 재조합 + 강풍. 체크포인트 1개만.

## 6. 실패와 되감기

- **게임 오버 없음.** 눈덩이가 굴러 떨어져도 화면 전환 없이 그냥 굴러간다.
- 눈덩이가 체크포인트보다 **15m 이상** 아래로 내려가면 → 체크포인트로 복귀
- 되감기 시 **눈덩이 크기는 유지**된다 (성장까지 되돌리면 너무 가혹)
- 되감으면 악력 게이지는 가득 채워준다 (벌을 두 번 줄 이유가 없다)

## 7. 엔딩

집 문 앞 **골 지점**에 눈덩이를 올리면 종료. 눈덩이 최종 지름으로 분기한다.

| 조건 | 엔딩 | 연출 |
|---|---|---|
| 지름 ≥ 1.6 m | **A — 완성** | 머리가 딱 맞게 올라간다 |
| 1.0 ≤ 지름 < 1.6 | **B — 작은 눈사람** | 머리가 좀 작다. 그래도 눈사람이다 |
| 지름 < 1.0 m | **C — 거의 다 녹았다** | 남은 눈을 뭉쳐 올린다 |

셋 다 "실패"가 아니다. 기록(시간 / 되감기 횟수 / 최종 지름)만 남긴다.

## 8. HUD

최소한으로. 화면을 덮지 않는다.

- **악력 게이지** — 눈덩이 위에 월드 스페이스로. 무제한 설정이면 숨김
- **눈덩이 지름 + 목표 진행 막대** — 좌하단
- **스테이지 이름** — 진입 시 2초간 페이드
- 미니맵 없음. 목표(집)는 지형으로 보이게 만든다.
