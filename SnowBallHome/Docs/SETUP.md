## 1. 지금 바로 할 일

에디터가 열려 있다면 스크립트가 자동으로 컴파일됩니다. Console에 에러가 없는지 먼저 확인하세요.

그다음 상단 메뉴:

```
SnowBall > 새 씬에 코스 생성 + 저장
```

이걸 누르면 새 씬을 만들어 코스를 통째로 넣고
`Assets/02_SnowBall/Scenes/SnowBall_Play.unity` 로 저장합니다. 그 뒤 ▶ Play.

| 메뉴 | 동작 |
|---|---|
| `새 씬에 코스 생성 + 저장` | 전체 코스 380m, 6스테이지 → `SnowBall_Play.unity` |
| `연습용 짧은 코스 (전 구간 압축)` | **190m, 6스테이지 전부** → `SnowBall_Practice.unity` (**한 바퀴 돌아볼 때**) |
| `튜닝용 (① 눈밭만)` | 50m 한 구간 → `SnowBall_Tuning.unity` (조작감 하나만 볼 때) |
| `코스 생성 (그레이박스)` | **현재 열린 씬**에 코스를 생성 |
| `코스 삭제` | 현재 씬의 코스만 제거 |

처음 실행하면 아래가 자동으로 만들어집니다.

| 생성물 | 내용 |
|---|---|
| `== SnowBall Course ==` | 6개 스테이지 지형 + 장애물 + 체크포인트 + 골 지점 |
| `Player` / `Snowball` / `GameManager` | 아이, 눈덩이, 진행 관리 + HUD |
| `Tuning/SnowBallTuning.asset` | 조작감 수치 전부 |

| `Materials/` | 그레이박스용 색 재질 12종 |
| `Prefabs/ThrownSnowball.prefab` | 마을 아이가 던지는 눈덩이 |

> ⚠️ **씬에서 손으로 옮긴 것은 재생성 때 전부 날아갑니다.**

## 2. 조작

| 입력 | 동작 |
|---|---|
| `W A S D` | 이동. **키를 떼면 그 프레임에 멈춥니다** (빙판 제외) |
| | 눈덩이를 밀 때 3.2 m/s. 맨몸으로 **계속 달리면** 0.45초에 걸쳐 5.0 m/s까지 |
| `Shift` 홀드 | 눈덩이 붙잡기. **잡는 동안 이동 불가**. 달리면서도 잡을 수 있습니다 |
| 잡은 채 `WASD` | 자동으로 손을 뗍니다. 다시 잡으려면 Shift를 놓았다 다시 누르세요 |
| 마우스 | 카메라 회전 (커서가 잠깁니다. Play 중지는 Esc가 아니라 에디터의 ■ 버튼) |
| `R` | **즉시 재시작** — 마지막 체크포인트로 바로 복귀 |
| `F` | 지금 자리를 체크포인트로 저장 (눈덩이가 멈춰 있어야 함) |
| `Esc` | 설정 패널 (마우스 감도, 상하 반전, 시야각) |

### 설정은 왜 Tuning 에셋과 분리했나

`SnowBallTuning` 은 **에셋**입니다. 런타임에 값을 바꾸면 에디터에서는 에셋 파일이
실제로 수정되어 다음 실행에도 남습니다 — 기획자가 정한 기본값이 플레이어의
감도 조절 때문에 조용히 덮어써지는 사고가 납니다.

그래서 `GameSettings`(PlayerPrefs 저장)를 따로 뒀습니다.
Tuning 은 **기본값**만 제공하고, 실제로 쓰이는 값은 `GameSettings` 에서 읽습니다.

나중에 정식 설정 화면은 `GameSettings` 만 읽고 쓰면 되므로,
지금의 `SettingsOverlay.cs`(IMGUI 임시 패널)는 통째로 버려도 됩니다.

체크포인트는 세 가지 경로로 정해집니다. 셋 다 같은 방식으로 처리됩니다.

1. **게임 시작 지점** — 시작하자마자 자동으로 잡힙니다
2. **자동 체크포인트** — 코스에 배치된 트리거를 눈덩이가 통과할 때
3. **수동 저장** — `R` 짧게 누르기. 위 둘을 덮어씁니다

눈덩이가 체크포인트보다 **15m 아래**로 떨어지면 자동으로 복귀합니다.

## 3. 튜닝 — 여기만 만지면 됩니다

`Assets/02_SnowBall/Tuning/SnowBallTuning.asset`

| 증상 | 만질 값 |
|---|---|
| 눈덩이가 너무 안 밀린다 | `pushForce` ↑ 또는 `massPerDiameterCubed` ↓ |
| 눈덩이가 너무 가볍다 | `massPerDiameterCubed` ↑ (지름³에 곱해지니 조금만 올려도 크게 변합니다) |
| 아이가 눈덩이를 뚫고 지나간다 | `pushOverrunTolerance` ↓ |
| 경사에서 눈덩이가 너무 빨리 내려간다 | `snowLinearDamping` ↑, `maxRollSpeed` ↓, 또는 스테이지 `slopeDegrees` ↓ |
| 잡아도 눈덩이가 슬슬 밀린다 | `grabFullyLocks` 가 켜져 있는지 확인 (기본 켜짐 = 완전 고정) |
| 반대로 잡았을 때 조금 흐르는 맛을 원한다 | `grabFullyLocks` 끄고 `grabHoldDamping` 으로 조절 (낮을수록 많이 미끄러짐) |
| 잡기가 너무 빡빡하다 | `grabReach` ↑, `grabFacingThreshold` ↓ |
| 악력이 너무 빨리 닳는다 | `gripDrainOnSlope` ↓ |
| **악력 게이지를 아예 끄고 싶다** | `gripDrainFlat = 0`, `gripDrainOnSlope = 0` → 무제한이 되고 HUD에서도 사라집니다 |
| 빙판이 안 미끄럽다 | `iceDeceleration` ↓, `iceLinearDamping` ↓ |
| 카메라가 너무 민감하다 | `mouseSensitivity` ↓ (기본 0.12) |

레벨 수치는 `CourseDefinition.asset` — 스테이지별 경사/폭/길이/장애물 개수를 고치고 다시 생성하면 됩니다.

## 5. 설계상 중요한 세 가지

### ① 아이는 힘이 아니라 **속도**로 움직인다

"키를 떼면 즉시 정지"는 `AddForce` 로는 불가능합니다(가속/감속 곡선이 생김).
그래서 `PlayerMotor` 는 수평 속도를 매 `FixedUpdate` 마다 직접 덮어씁니다.
입력도 `Update` 가 아닌 `FixedUpdate` 에서 읽습니다 — 한 프레임 안에서 `FixedUpdate` 가
먼저 돌기 때문에, `Update` 에서 읽으면 항상 한 프레임 묵은 입력으로 계산됩니다.

부작용으로 아이가 사실상 무한한 힘을 갖게 되어 무거운 눈덩이도 평지처럼
밀어버릴 수 있는데, 이건 `ClampSpeedAgainstSnowball()` 이 막습니다 —
**밀고 있는 동안 아이의 속도는 눈덩이 속도에 묶입니다.**
이게 질량 설계를 살리는 장치라, 함부로 빼면 무게감이 전부 사라집니다.

### ② 잡기는 `isKinematic` 이 아니라 **위치 고정**으로 한다

`isKinematic = true` 로 만들면 눈덩이가 무한 질량 벽이 되어
경사 아래쪽에 있는 아이를 밀어내고, 놓는 순간 속도가 0에서 튑니다.

그렇다고 속도만 감쇠시키면 **경사에서 계속 흐릅니다.**
중력이 매 스텝 속도를 더하므로 감쇠와 평형을 이루는 지점이 생기고,
20° 경사·감쇠 14 기준 약 0.2 m/s 로 스멀스멀 밀립니다.

그래서 `ApplyGrabHold()` 는 잡은 순간의 위치(`holdAnchor`)를 기억해두고,
매 `FixedUpdate` 마다 속도를 0으로 만든 뒤 **그 위치로 되돌립니다.** 흐름이 0이 됩니다.

흐르는 맛을 다시 원하면 `grabFullyLocks` 를 끄면 예전 감쇠 방식으로 돌아갑니다.

### ③ 바닥 판정은 충돌 이벤트가 아니라 **매 프레임 탐사**로 한다

`OnCollisionEnter/Exit` 로 빙판을 판정하면, 타일 A→B 로 넘어갈 때
`Exit(A)` 가 `isOnIce` 를 꺼버려 빙판 위인데도 일반 바닥으로 깜빡입니다.
`GroundSampler` 는 매 `FixedUpdate` 마다 발밑을 구체로 훑어서
이 문제를 구조적으로 없애고, 덤으로 **경사각**(악력 소모 계산에 필요)까지 얻습니다.

`Rigidbody` 가 붙은 콜라이더는 바닥에서 제외합니다 —
안 그러면 아이 발밑 구체가 **바로 앞의 눈덩이**를 바닥으로 잡아버립니다.

## 5-1. 지형 구조 — 섹션이 쌓인 타워

`Getting Over It`, `Chained Together`, `Get To Work` 처럼
**성격이 다른 섹션이 수직으로 쌓인 구조**입니다.

```
         ╔════╗        ⑥ 마지막 산길   ← 정상 (집)
      ───╢    ╟───     테라스
       ╔═╩════╩═╗      ⑤ 마을
    ───╢        ╟───   테라스
     ╔═╩════════╩═╗    ④ 강아지
  ───╢            ╟─── 테라스
   ╔═╩════════════╩═╗  ③ 계곡
───╢                ╟───
 ...                     ② 숲 / ① 눈밭
└────────────────────┘ 타워 발치 바닥
```

각 섹션은 **일정한 반지름**으로 돌고, 섹션이 바뀔 때만 반지름이 한 단계 줄어듭니다
(22m → 10m). 연속으로 줄이면 그냥 원뿔이 되어 층이 안 보입니다.

**섹션 경계마다 도넛 모양 테라스**가 깔립니다. 이게 층을 만들어내는 실체입니다.
위 섹션은 안쪽에서 돌기 때문에 이 고리가 그 바깥에 남고,
바깥으로 굴러 떨어지면 바닥까지 가지 않고 **자기 섹션 바닥에 착지**합니다.

- 안쪽(타워 중심)은 **항상 벽** — 중심으로는 떨어질 수 없습니다
- 바깥쪽은 **열려 있습니다** (① 눈밭만 난간)
- 테라스 바깥 가장자리에는 **턱**이 있어 또 굴러 나가지 않습니다
- 맨 아래에서 떨어지면 타워 발치 바닥이 받습니다

전체 규모는 미니게임 기준입니다 — **길이 약 240m, 높이 약 52m, 6섹션.**
한 섹션이 30~45초, 전체 4~6분 정도를 의도했습니다.

> ⚠️ **`fallRespawnDepth` 는 층간 높이보다 커야 합니다.**
> 작으면 아래층에 착지하기 전에 되감겨서 이 설계가 통째로 죽습니다.
> 코스 생성 로그에 층간 높이가 찍히니 그걸 보고 맞추세요. (현재 32m)

| 값 | 기본 | 효과 |
|---|---|---|
| `spiralTower` | 켜짐 | 끄면 예전처럼 한 줄로 뻗습니다 |
| `towerBaseRadius` | 22 | 맨 아래 반지름 |
| `towerTopRadius` | 10 | 맨 위 반지름. base 와의 차이가 클수록 층이 많이 어긋남 |
| `towerInnerWallHeight` | 2.5 | 안쪽 벽 높이 |
| `segmentLength` | 3.5 | 나선은 잘게 쪼개야 매끄럽습니다 |

## 5-2. 복구 설계 — Get To Work 방식

`Get To Work` 가 "떨어져도 불쾌하지 않다"를 만든 방법은
**떨어짐을 막은 게 아니라 재시도를 공짜로 만든 것**입니다.
스토어 설명대로 "give up button" 한 번이면 구간이 즉시 다시 시작되고, 페널티는 없습니다.

그래서 이 게임도 같은 원칙을 따릅니다.

| 원칙 | 구현 |
|---|---|
| 떨어짐은 막지 않는다 | 난간은 ① 눈밭에만. 나머지는 낭떠러지 |
| 재시도는 공짜다 | `R` 한 번 = 즉시 복귀. 홀드 없음, 페이드 0.12초 |
| 잃는 건 20~30초뿐 | 체크포인트를 20~25m 마다 (총 33개) |
| 벌은 없다 | 눈덩이 크기 유지, 악력 회복, 게임 오버 없음 |

> **안전 지대(에이프런)는 기본으로 꺼져 있습니다.**
> 한때 길 아래에 넓은 복구 지대와 램프를 깔아뒀는데, 떨어져도 안 죽는 대신
> **걸어서 되돌아가는 지루함**이 생겼습니다. 정확히 반대 방향의 해법이었습니다.
> `CourseDefinition > buildRecoveryApron` 으로 다시 켤 수는 있지만,
> `R` 즉시 재시작과 같이 쓰면 둘 다 의미가 없어집니다.

지형 관련 값:

| 값 | 기본 | 효과 |
|---|---|---|
| `checkpointCount` (스테이지별) | 4~8 | 촘촘할수록 한 번에 잃는 시간이 짧아짐 |
| `rails` (스테이지별) | ①만 켜짐 | 켜면 그 구간은 떨어질 수 없음 |
| `segmentOverlap` | 1.2 | 바닥 판을 겹쳐 굽이 바깥쪽 틈을 메움 |
| `slopeVariance` | 3.5 | 구간별 경사 흔들림. 0이면 평평한 비탈 |
| `fallRespawnDepth` (Tuning) | 8 | 낮을수록 빨리 복귀 — 허공 낙하 시간이 곧 지루함 |
| `respawnFadeDuration` (Tuning) | 0.12 | 복구에 걸리는 시간. 길수록 마찰이 쌓임 |

## 7. 다음 단계 (조작감 튜닝)

① 눈밭만 놓고 다음을 확인하는 것이 목표입니다.

- [ ] WASD를 뗐을 때 **정말로** 즉시 멈추는가
- [ ] 눈덩이를 밀 때 무게가 느껴지는가 (너무 가볍지도, 벽 같지도 않게)
- [ ] 경사에서 손을 떼면 굴러 내려가는 게 **무섭게** 느껴지는가
- [ ] Shift로 붙잡는 순간 "버티고 있다"는 감각이 오는가
- [ ] 잡기→놓기→밀기 사이클이 5~15초 리듬으로 돌아가는가
